## 一、什么是 RAG，为什么需要它

### 1.1 定义

**RAG（检索增强生成）** 是一种将「信息检索」与「大语言模型（LLM）生成」相结合的架构范式。其核心思想是：在让 LLM 回答问题之前，先从外部知识库（文档、数据库、网页等）中**检索出与问题相关的证据片段**，把这些证据作为上下文拼接进提示词（Prompt），再由 LLM 基于「证据 + 问题」生成答案。

一句话概括：**先检索、再生成；让模型的回答有据可依。**

### 1.2 为什么需要 RAG

大语言模型本身存在若干固有问题，RAG 正是为弥补这些问题而生：

| 问题 | 说明 | RAG 的解决方式 |
| --- | --- | --- |
| **知识时效性** | 模型训练后知识冻结，无法知道最新事件 | 知识库可随时更新，检索实时最新内容 |
| **领域知识缺失** | 通用模型缺乏企业私有/垂直领域知识 | 检索企业内部文档，注入专属上下文 |
| **幻觉（Hallucination）** | 模型会编造看似合理但错误的内容 | 强制基于检索证据回答，可溯源 |
| **黑盒不可信** | 回答无出处，难以审计 | 答案可附带引用来源（citation） |
| **训练成本高** | 微调模型代价高昂 | 无需重新训练，更新知识库即可 |

### 1.3 RAG vs 微调（Fine-tuning）

| 维度 | RAG | 微调 |
| --- | --- | --- |
| 知识更新 | 改知识库即可，实时 | 需重新训练，成本高 |
| 可解释性 | 高（有出处） | 低 |
| 适用场景 | 知识频繁变化、需引用来源 | 学习特定风格/格式/任务模式 |
| 成本 | 较低（主要是检索+推理） | 较高（数据、算力） |
| 幻觉控制 | 强 | 弱 |

> 实践中二者并不互斥：**RAG 负责「补充知识」，微调负责「调整行为/风格」**，可组合使用。

## 二、RAG 发展路径总览

RAG 自 2020 年 Facebook AI 提出以来，经历了从「朴素管道」到「智能体工作流」的演化，业界普遍将其划分为以下演进阶段：

```
2020  Naive RAG ──► 2023  Advanced RAG ──► 2023  Modular RAG ──► 2024  Agentic RAG ──► 2024+  Frontier (GraphRAG/多模态/评测)
  (基础管道)          (检索全链路优化)        (模块化编排)            (智能体决策)            (前沿融合)
```

- **Naive RAG**：确立「索引-检索-生成」三段式基础管道。
- **Advanced RAG**：在检索前/中/后三个环节做精细优化（改写、混合检索、重排序等）。
- **Modular RAG**：将上述优化拆成可复用模块，支持非线性编排（图式、循环、分支）。
- **Agentic RAG**：引入智能体（Agent），由模型自主决策检索时机、工具与多步策略。
- **Frontier**：与知识图谱、多模态、长上下文、评测体系深度融合，并向工程化/产品化演进。

## 三、五个阶段的演进地图

| 阶段 | 核心特征 | 关键能力 | 代表技术 | 痛点/局限 |
| --- | --- | --- | --- | --- |
| **① 基础 RAG** | 线性管道 | 文档→切块→向量化→相似度检索→拼接生成 | FAISS、OpenAI Embeddings | 召回噪声大、分块割裂、缺乏优化 |
| **② 进阶 RAG** | 全链路优化 | 查询改写 / 混合检索 / 重排序 / 语义分块 | Hybrid Search、Cross-Encoder Rerank、Parent-Child Chunk | 流程固定，无法应对复杂问题 |
| **③ 模块化 RAG** | 模块可编排 | 流程图、循环、路由、子模块替换 | Rewrite-Retrieve-Read、FiD、RETRO | 仍以静态图为主，缺乏自主决策 |
| **④ 智能体化 RAG** | 自主决策 | 多步检索、工具调用、自我反思、纠错 | Self-RAG、CRAG、Agentic RAG、LangGraph | 延迟与成本上升、需编排治理 |
| **⑤ 前沿趋势** | 融合增强 | 图谱、多模态、评测、长上下文协同 | GraphRAG、MM-RAG、RAGAS | 工程复杂、评测标准不统一 |

## 四、技术选型与学习路线建议

### 4.1 按需求选择阶段

- **快速验证 / 简单 FAQ 机器人**：基础 RAG + 向量库即可。
- **对准确率要求高 / 文档量大**：进阶 RAG（混合检索 + 重排序 + 语义分块）。
- **多源、多类型知识、流程复杂**：模块化 RAG（可编排管道）。
- **开放式、多跳、需推理的问答**：智能体化 RAG（Agent 自主决策）。
- **全局性摘要 / 跨文档洞察 / 多模态**：前沿方案（GraphRAG、多模态 RAG）。

### 4.2 推荐学习路线

1. 先吃透 **基础 RAG** 全流程（索引、检索、生成），理解每个环节的作用。
2. 针对真实痛点，逐步引入 **进阶 RAG** 优化（从「查询改写 + 重排序」入手性价比最高）。
3. 当流程变复杂时，学习 **模块化 RAG** 的编排思想（理解模块边界）。
4. 结合你的 **AI Agent** 学习目标，重点攻克 **智能体化 RAG**（用 Agent 做检索决策）。
5. 最后补齐 **评测体系** 与 **前沿方向**，形成闭环。
