## 一、GraphRAG：知识图谱增强

### 1.1 动机

传统 RAG 检索「扁平文本块」，擅长**局部、点状**问题（"某条款怎么写"），但面对**全局、聚合**问题（"整个数据集的主要主题是什么""各角色间关系如何"）时，零散 chunk 无法支撑高层总结。

### 1.2 微软 GraphRAG 做法

1. **实体/关系抽取**：用 LLM 从文档中抽取实体（人物、组织、概念）与关系，构建**知识图谱**。
2. **社区检测（Community Detection）**：用 Leiden 算法把图谱分成多个社区（主题簇）。
3. **社区摘要（Community Summarization）**：对每个社区让 LLM 生成摘要，形成"自底向上"的层级化知识。
4. **查询时**：
   - **全局问题** → 借助社区摘要做高层聚合；
   - **局部问题** → 仍走图遍历 + 向量检索。
5. **Token 开销**：建图与摘要成本高（一次性离线），但查询时命中率高、答案更具全局视野。

### 1.3 适用场景

- 法律/科研文献的宏观趋势分析
- 企业知识库的"全局洞察"与"关系问答"
- 任何需要"跨文档综合"的任务

> 代价：构建与维护图谱成本高、更新复杂；适合"知识相对稳定、查询偏全局"的场景。

## 二、多模态 RAG（MM-RAG）

### 2.1 定义

把检索与生成从"纯文本"扩展到**图像、表格、音频、视频**等多模态内容。

### 2.2 关键能力

- **多模态嵌入**：用 CLIP / 多模态 Embedding 把图片、文本映射到同一向量空间，实现"以文搜图、以图搜文"。
- **表格 RAG**：把表格转为文本/结构化表示后检索，或用 Text-to-SQL 直接查表。
- **文档视觉 RAG**：对 PDF 页面截图做视觉理解（如 ColPali 用视觉语言模型直接检索页面图像）。
- **视频/音频 RAG**：对音视频做转写 + 时间戳索引，按片段检索。

### 2.3 挑战

- 跨模态对齐难；
- 多模态 LLM 上下文与成本；
- 评测标准不成熟。

## 三、长上下文模型 vs RAG

### 3.1 争议

随 LLM 上下文窗口扩大（100K~1M+ token），出现疑问：**"长上下文能否取代 RAG？"**

### 3.2 结论：互补而非替代

| 维度 | 长上下文 | RAG |
| --- | --- | --- |
| 知识更新 | 需重新喂入，贵 | 改库即可，便宜 |
| 超大规模知识 | 放不下全量 | 按需取，可扩展到海量 |
| 注意力稀释 | 长文本中间信息易被忽略（"Lost in the Middle"） | 只喂相关证据，聚焦 |
| 溯源 | 弱 | 强（带引用） |
| 成本 | 高（每次都处理长文本） | 低（只处理相关块） |

- **最佳实践**：**用 RAG 做"精准召回 + 溯源"，把检索到的精炼证据放入长上下文**，二者协同。长上下文解决了"上下文装不下几段证据"的问题，但没解决"从海量知识里找什么"的问题。
- 趋势方向：**RAG + 长上下文**（先检索再放进长窗口）、**self-extend / 上下文压缩**。

## 四、训练式 RAG 与微调协同

### 4.1 思路

前面所有 RAG 都是"推理时（inference-time）"增强。训练式 RAG 在**训练阶段**就让模型学会"如何更好地检索与利用检索结果"。

### 4.2 代表

- **RA-DIT（Retrieve-Augment fine-Tune）**：同时微调**检索器**和**生成器**，让两者协同。
- **In-Context RALM**：在上下文里注入检索示范，引导模型利用检索内容。
- **RETRO / ATLAS**：把检索结构融入模型架构（见 03 篇）。

### 4.3 与微调的关系（再次强调）

- **RAG**：补"知识"（what）。
- **微调**：调"行为/风格/格式"（how）。
- 二者组合：**RAG + 领域微调** 是很多生产系统的终极形态。

## 五、RAG 评测体系（核心闭环）

> 没有评测，所有优化都是"凭感觉"。评测是把前面四个阶段串成**持续改进闭环**的关键。

### 5.1 三大核心指标

| 指标 | 含义 | 关注点 |
| --- | --- | --- |
| **Context Relevance / Precision** | 检索到的内容是否相关 | 检索质量 |
| **Faithfulness（忠实度）** | 答案是否基于检索证据、有无幻觉 | 生成质量 |
| **Answer Relevancy（答案相关性）** | 答案是否切题、解决用户问题 | 端到端质量 |
| **Context Recall** | 该检索的相关内容是否都被召回 | 检索召回 |

### 5.2 常用评测框架

- **RAGAS**：开源主流，用 LLM 自动打分上述指标，支持无人工标注快速迭代。
- **TruLens**：提供 RAG 三元组（Context Relevance / Groundedness / Answer Relevance）评估与追踪。
- **DeepEval / ARES**：单元测试式评测、自动生成评测集。
- **人工评测**：黄金标准，用于校验自动指标。

### 5.3 评测闭环建议

```
构建评测集(问题+标准答案/标准上下文)
   → 跑当前 RAG 管线 → RAGAS 打分
   → 定位短板(检索?生成?) → 针对性优化(改写/重排/...)
   → 再评测 → 对比指标是否提升
```

> 建议：从进阶 RAG 阶段起，就固定一套评测集，每次改动都跑分对比——这是区分"玩具"与"生产级"的分水岭。

## 六、工程化与可观测性

- **可观测性**：记录每次查询的改写、检索结果、重排分数、工具调用、token 消耗（LangSmith、Phoenix、Langfuse）。
- **缓存**：对高频查询做检索/生成缓存，降成本。
- **流式与并发**：生产需支持流式输出、并发检索。
- **安全与权限**：检索结果需做**权限过滤**（用户只能看其有权访问的文档），防止越权泄露。
- **降级策略**：检索失败时兜底（转网页搜索 / 转人工 / 显式告知"无可靠资料"）。

## 全文总结：RAG 演进一图流

```
基础 RAG ──► 进阶 RAG ──► 模块化 RAG ──► 智能体化 RAG ──► 前沿融合
 索引-检索-生成   全链路优化   模块可编排       Agent 自主决策   图谱/多模态/评测
   (管道)        (提准确率)    (架构灵活)       (会思考的工作流)  (工程化闭环)
```

> 学习建议：不要一上来就追最复杂的 Agentic / GraphRAG。**先把基础与进阶打牢、用评测验证收益，再在真正复杂的场景引入智能体与图谱。** 循序渐进，方能扎实。
