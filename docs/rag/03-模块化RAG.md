# 阶段三：模块化 RAG（Modular RAG）

> 当进阶 RAG 的优化项越堆越多，流程从「一条直线」变成「带分支、循环、多路」的复杂网络。模块化 RAG 把每个能力抽象成**可替换、可组合的模块**，并用统一的「编排范式」把它们串起来。这是从「调参式优化」走向「架构式设计」的关键一步。

## 一、为什么需要模块化 RAG

进阶 RAG 把所有优化「硬编码」进一个固定三步管道，带来两个问题：

1. **流程僵化**：现实问题千差万别——有的需要查询改写，有的需要多跳检索，有的不需要检索直接回答。固定管道无法自适应。
2. **难以维护与扩展**：每加一个优化就改一遍主干代码，耦合严重。

模块化 RAG 的回答是：**把「检索、生成、改写、重排、记忆、路由」等能力变成独立模块，像搭积木一样按任务自由组合，并支持循环（迭代检索）与分支（路由）。**

## 二、核心思想：模块与编排

### 2.1 常见模块清单

| 模块 | 职责 | 对应前文优化 |
| --- | --- | --- |
| **Search（检索）** | 从索引取候选 | 向量/混合检索 |
| **Retrieve（召回）** | 具体取数逻辑 | Top-K |
| **Rewrite（改写）** | 改写/扩展查询 | 查询改写、HyDE |
| **Rerank（重排）** | 候选精排 | Cross-Encoder |
| **Filter（过滤）** | 元数据/规则过滤 | 元数据过滤 |
| **Read / Generate（生成）** | LLM 生成答案 | 上下文拼接 |
| **Memory（记忆）** | 多轮上下文/历史 | 对话状态 |
| **Fuse（融合）** | 多路结果合并 | RAG-Fusion / RRF |
| **Judge / Route（判断/路由）** | 决策下一步走向 | 路由分支 |

### 2.2 三种基本拓扑

```
(1) 线性（Linear）        (2) 分支/路由（Routing）      (3) 循环（Loop）
 A → B → C → D             A →[路由]→ B1 ┐              A → B →(判断)─否─┐
                          A →[路由]→ B2 ├→ C           A → B →(判断)─是─┘
                                         ↓
```

- **线性**：经典管道（基础/进阶 RAG）。
- **分支**：根据问题类型走不同检索路径（如「数值问题走数据库，概念问题走文档」）。
- **循环**：检索→判断→不足则再检索（为智能体阶段铺垫）。

> 模块化 RAG 的价值在于：**同一套模块，可拼出不同范式**，无需为每个新场景重写整套代码。

## 三、代表性范式（Rewrite-Retrieve-Read 等）

学术与工程界在模块化思想下提出多种「范式（Pattern）」，下面列出最具影响力的几种。

### 3.1 Rewrite-Retrieve-Read（RRR）

- **来源**：Ma et al., 2023（*Query Rewriting for Retrieval-Augmented Large Language Models*）。
- **结构**：`Rewrite 模块` 先把问题改写成检索友好的查询 → `Retrieve` → `Read`。
- **亮点**：Rewrite 模块的提示词可用**强化学习/梯度**优化，让改写器学会"怎么问更容易检索到答案"。
- **对应**：把「查询改写」提升为范式级第一环。

### 3.2 Generate-Read（先生成后读）

- **结构**：先让 LLM 基于自身知识**生成一段草稿/假设答案**，再以草稿为线索去检索验证/补充。
- **与 HyDE 关系**：思路同源（先"假设"再检索），HyDE 可视为其轻量实现。

### 3.3 Recite-Read（背诵式）

- **结构**：先让模型"背诵"相关记忆（参数内知识），再检索外部知识补充。
- **适用**：模型本身已含部分知识、需外部校验的场景。

### 3.4 Demonstrate-Search-Predict（DSP）

- **来源**：Stanford（*DSP: Compiling Declarative Language Model Calls*）。
- **结构**：用「示例（demonstration）+ 检索 + 预测」组合，把 RAG 流程用声明式编程表达。
- **意义**：把 RAG 当成可编程的"模块组合语言"，影响后续编排框架设计。

### 3.5 Iter-RetGen（迭代检索-生成）

- **结构**：`生成 → 检索 → 再生成` 交替进行，每轮用上轮生成内容指导新一轮检索。
- **价值**：适合需要逐步推理、逐步补充证据的多跳问题。

### 3.6 RAPTOR（递归抽象树）

- **来源**：Sarthi et al., 2024。
- **结构**：对检索到的 chunk 做**层级聚类 + 逐层摘要**，构建"叶子（原文）→ 枝（摘要）→ 干（高层摘要）"的树；回答时从不同层级取信息。
- **价值**：擅长「全局性、总结性」问题（如"整本书的核心观点是什么"），为 GraphRAG 之外另一条"结构化聚合"路线。

## 四、图式检索（Graph-based RAG）

- **思想**：把检索对象从「扁平 chunk」升级为「图结构」——节点是文本/实体，边是关系。
- **检索方式**：沿图做游走/子图抽取（如从"苹果公司"节点扩展到"CEO→产品→供应链"相关子图）。
- **价值**：天然支持多跳关系推理，是后续 **GraphRAG（见 05 篇）** 的学术前身。
- **代表**：早期基于 Knowledge Graph + 向量；如今与 LLM 抽取实体关系结合（微软 GraphRAG 属于此脉络的集大成者）。

## 五、学术代表工作：REALM / DPR / FiD / RETRO

这些工作奠定了"检索增强"在**模型训练/架构层面**的基础，理解它们有助于看清 RAG 的来路。

### 5.1 REALM（2020）—— RAG 的思想先驱

- **贡献**：首次把「神经检索器 + 知识增强生成」端到端联合训练，用检索结果做Masked LM 的完形填空。
- **意义**：证明"检索"可以融入预训练范式。

### 5.2 DPR（Dense Passage Retrieval, 2020）

- **贡献**：提出**双塔（Bi-Encoder）稠密检索**训练方法，用问题编码器 + 段落编码器分别编码，用对比学习拉近距离。
- **意义**：今天所有向量检索/Embedding 检索的直接鼻祖；FAISS 式检索的"正确打开方式"由它定型。

### 5.3 FiD（Fusion-in-Decoder, 2021）

- **贡献**：检索 Top-K 文档后，**先不拼接**，而是各自编码（Encoder 独立处理每个文档），仅在 Decoder 阶段做**融合（Fusion）**。
- **价值**：突破"上下文必须拼在一起"的限制，降低输入长度压力、提升多文档利用能力。
- **对应**：你会在许多生产框架中看到"先各自编码、后融合"的影子。

### 5.4 RETRO（2021, DeepMind）

- **贡献**：把检索融入**大规模语言模型架构**（数十亿参数），用检索到的片段做「chunked cross-attention」，证明"检索增强可以让小模型逼近更大模型的效果"。
- **意义**：检索不只是"外挂 Prompt"，也可以成为模型架构的一部分；直接影响后续训练式 RAG（05 篇）。

## 六、模块化 RAG 与进阶 RAG 的关系

- **进阶 RAG** 是「在固定管道里加优化」，偏**工程技巧清单**。
- **模块化 RAG** 是「把优化抽象成模块 + 可编排拓扑」，偏**架构设计方法**。
- 二者是**递进而非替代**：模块化 RAG 把进阶 RAG 的所有优化（改写、混合、重排、压缩）收纳为可插拔模块，并进一步允许**循环与分支**。
- 它仍是「**静态图**」——流程在部署时确定，运行中不能真正"自主决策"。**真正的自主决策，要等到智能体化 RAG。**
